The State of AI Code

What 6 coding agents leave behind, measured commit by commit in 336 public JavaScript and TypeScript repos, and compared with the humans working in those same repos.

Lines deleted for every 100 added

Claude, Copilot and Jules delete 36–62% less than the humans they work with.

A healthy codebase gets pruned: old versions removed, dead helpers deleted, two ways of doing a thing folded into one. Claude, Copilot and Jules deleted clearly less for each line they added than the humans committing to the same repos. No agent deleted more. For Cursor, Codex and Devin, the difference is within the noise.

Each row compares an agent with the humans in the repos where both wrote at least 300 lines. The range is a 90% bootstrap interval over repos: “within noise” means it includes 1×.

Commit size

Claude, Cursor and Codex add 1.8–2.3× as many lines per commit as humans.

The median human commit added 63 lines of JavaScript or TypeScript. Big commits are harder to review, and review is where dead code and shortcuts get caught.

Shortcuts per 1,000 lines added

Claude and Codex take fewer shortcuts than the humans they work with.

A shortcut makes a check pass without fixing what it found: @ts-ignore, eslint-disable without a reason, as any, .skip and .only on tests, an empty catch, or a branch on NODE_ENV === 'test'. For Cursor, Copilot, Devin and Jules, the sample can't tell them apart from humans. For every author, humans included, the most common shortcut is as any.

Dead code per 1,000 lines added

Claude, Copilot and Devin leave less of their own code dead than humans do.

Lines each author wrote in the last year that now sit in files nothing imports or names. Claude, Copilot and Devin left clearly less of their own code dead than the humans in the same repos. Dead lines are credited to whoever wrote them, not to whoever stopped using them: when an agent writes a replacement and leaves the old file behind, those lines count against the person who wrote the original. Read it together with the deletion numbers above. This is also the noisiest measure here, since a file only a framework loads by name can look unused.

Method

How this was measured

  • Repos. Public, non-fork JavaScript and TypeScript repos under 300 MB with commits signed by each agent, found with GitHub commit search (for example the Co-Authored-By: Claude trailer, cursoragent@cursor.com, or commits by copilot-swe-agent[bot]), up to 60 of the most-starred per agent.
  • Commits. The last 400 commits of each repo's default branch, counting non-merge commits since October 1, 2025, by everyone. A commit belongs to an agent when the agent is its author or co-author. Build output, vendored and minified files, files adding over 3,000 lines and commits adding over 20,000 are skipped as generated.
  • “Humans” means commits no agent signed. Agents that don't sign their commits count as human here, so the gaps shown are, if anything, smaller than the real ones.
  • Dead code is a file no other file imports or names, outside folders frameworks load by path, with its lines credited through git blame. Repos using auto-imports (Nuxt) are left out of this measure.
  • Uncertainty. Each range resamples repos 1,000 times. Agents differ in which repos they work in, so every comparison is against the humans in the same repos.
  • Everything here was measured by zomb, and the script that produced it is in its repo, so you can check the work.
