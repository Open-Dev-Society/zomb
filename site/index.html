Four passes

It reads your repo the way a careful reviewer would, then tells you what to delete first.

Security, zombie code, sprawl and architecture, written to one HTML file. Nothing is uploaded.

Security

Holes an agent leaves open

  • API keys pasted into code, shown masked
  • committed .env files and secrets in NEXT_PUBLIC_*
  • routes that write data with no auth check
  • SQL and shell built from strings, eval, raw HTML
  • vulnerable production packages

Zombie code

Code nothing uses

  • files nothing imports or names
  • files only their own tests keep alive
  • unused packages and dead exports
  • pages and API routes nothing links to

Sprawl

Two of everything

  • lines added against lines deleted, month by month
  • three icon sets, two date libraries
  • LandingV2 next to Landing
  • copy-pasted blocks, helpers defined twice

Architecture

Shape that drifts

  • import cycles, files past 500 lines
  • shared code across utils/, lib/, helpers/
  • deep ../../../ imports
  • mixed file naming

Beyond the scan

It holds the line while the agent works, then cleans up after it.

1Blueprint

The rules your codebase already follows, written down once.

zomb blueprint proposes only rules the code mostly follows already, each with its evidence. Approve them once; every agent and every pull request is held to them.

.zomb/blueprint.ymlinferred, then approved
libraries:
  icons: "react-icons"          # 5 files; also lucide-react (1)
  http: "fetch"                 # 4 files
folders:
  components: "src/components"  # 31 of 31 components
  shared: "src/lib"             # 5 files
naming:
  components: "PascalCase"      # 27 of 27 component files
imports:
  alias: "@/"                   # 26 files import through it
api:
  auth: "required"              # 5 of 6 routes that change data check auth
files:
  maxLines: 500                 # 3 files over it today

2Guard

It stops the mess while the agent is still writing it.

With the Claude Code plugin, zomb checks every edit in about 50 ms. It reads only the lines being added, so removing a suppression is never punished.

3Pull requests

It checks what this change broke, not the debt you inherited.

zomb --save-baseline accepts today's findings, so only new ones fail a build. Add the GitHub Action, or install the app and skip the workflow file.

4Fix

Deleting is the one change a build can prove, so zomb does that part itself.

zomb fix works on a new branch. Your typecheck, lint, tests and build run first; the ones that pass judge every batch it deletes. A batch that breaks one is undone and retried item by item. No AI, no API key.
