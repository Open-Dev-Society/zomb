The scan01 / 06

One command, one report

It reads your repo the way a careful reviewer would, then tells you what to delete first.

Four passes — security, zombie code, sprawl, architecture — written to one HTML file. Nothing is uploaded.

Security

  • API keys pasted into code, shown masked
  • committed .env files
  • secrets shipped to the browser in NEXT_PUBLIC_*
  • routes that write to your database with no auth check
  • SQL and shell built from strings, eval, raw HTML
  • vulnerable production packages

Zombie code

  • files nothing imports or names
  • files only their own tests keep alive
  • unused packages and dead exports
  • pages and API routes nothing links to

Sprawl

  • lines added against lines deleted, month by month
  • three icon sets, two date libraries
  • LandingV2 next to Landing
  • copy-pasted blocks and helpers defined twice

Architecture

  • import cycles and files past 500 lines
  • shared code scattered across utils/, lib/, helpers/
  • deep ../../../ imports
  • mixed file naming

Fix06 / 06

The part a build can prove

Deleting is the one change a build can verify, so that is the part zomb does itself.

zomb fix works on a new branch. It runs your typecheck, lint, tests and build first and keeps the ones that pass as its gates, then deletes in small batches and re-runs them after each. A batch that breaks a check is undone and retried item by item, so anything that turns out to be needed is reported, not removed. No AI, no API key.

Run it on the repo you are least sure about.

$npx zomb
